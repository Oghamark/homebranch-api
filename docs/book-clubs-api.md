# Book Clubs API (instance-local core)

All routes require the existing JWT authentication guard. The authenticated account ID comes from the verified token; request bodies cannot set the club owner or actor identity. Club roles are local to one club and never grant instance administrator, library administration, or global book-sharing permissions.

## Domain model

- `BookClubEntity` stores name, optional description, `private`/`instance_visible` visibility, active/archived lifecycle, and owner account ID.
- `BookClubWorkEntity` stores a logical selected work's title/author plus optional ISBN, external work ID, edition ID, series, and series position. It does not point to a library book, file, hash, or format.
- `BookClubMemberEntity` stores the per-club account association and `owner`, `moderator`, or `member` role, plus `progress_sharing_enabled` (false by default). Its nullable `personal_book_id` remains a reserved legacy placeholder; this feature does not read, write, or return it.
- `BookClubReadingCopyEntity` stores at most one copy choice per club-member and logical work. `source` is `shared`, `personal`, or `none`; an optional local book ID identifies the chosen copy. Confirmed associations also record `associationMethod` (`identifier`, `metadata_candidate`, or `manual_confirmation`) and a `confidence` from 0 to 1. The association is instance-local and independent of file hash or format.
- `BookClubMilestoneEntity` stores ordered, format-neutral named `part`, `chapter`, or moderator-authored `checkpoint` milestones for the selected logical work. Club start/completion dates are optional.
- `BookClubMilestoneMappingEntity` stores a member-only mapping from a club milestone to that member's own edition label/ordinal. It is never included in another member's response.
- `BookClubMilestoneProgressEntity` stores only the member, logical work, milestone, coarse status (`not_started`, `in_progress`, `completed`), and optional 0–100 percentage. Sharing is opt-in and defaults off. No book ID, file format, CFI, page number, timestamp, annotation, or reader-history field is stored in this table.
- Clubs, memberships, reading-copy associations, and book pointers exist only in the current instance database. No synchronization, federation, cross-instance invitations, or data transfer is implemented.

## Routes

| Method   | Path                                                             | Behavior                                                                                                                                                      |
| -------- | ---------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `POST`   | `/book-clubs`                                                    | Create a club; caller becomes owner and initial member. Requires `name`, `visibility`, and `selectedWork: { title, author }`; optional `description`.         |
| `GET`    | `/book-clubs`                                                    | List active instance-visible clubs and private clubs for which caller is a member.                                                                            |
| `GET`    | `/book-clubs/:clubId`                                            | Read club and logical selected work. Private clubs require membership.                                                                                        |
| `GET`    | `/book-clubs/:clubId/schedule`                                   | Read dates and milestones as a member, plus only the caller's mapping/progress and opted-in coarse summaries.                                                   |
| `PUT`    | `/book-clubs/:clubId/schedule`                                   | Owner or moderator sets optional ISO start/completion dates and replaces the ordered milestone list.                                                          |
| `PUT`    | `/book-clubs/:clubId/progress-sharing`                           | Member opts in/out with `{ "enabled": true|false }`; default is false.                                                                                        |
| `PUT`    | `/book-clubs/:clubId/milestones/:milestoneId/mapping`            | Member maps a milestone to `{ "memberLabel": "Chapter 7", "memberPosition": 7 }` in their own edition.                                                   |
| `DELETE` | `/book-clubs/:clubId/milestones/:milestoneId/mapping`            | Remove the caller's private edition mapping.                                                                                                                   |
| `PUT`    | `/book-clubs/:clubId/milestones/:milestoneId/progress`           | Record `{ "status": "in_progress", "percentage": 42 }` for a milestone. Only the three coarse statuses and optional 0–100 percentage are accepted.           |
| `GET`    | `/book-clubs/:clubId/works/:workId/reading-copy`                 | Read the caller's choice for that club work, including `source`, match evidence, availability, and a minimal book summary when currently authorized.          |
| `GET`    | `/book-clubs/:clubId/works/:workId/reading-copy/matches`         | List up to 100 suggested local matches, prioritizing stable-identifier matches. Every candidate requires member confirmation; listing creates no association. |
| `POST`   | `/book-clubs/:clubId/works/:workId/reading-copy/matches/confirm` | Confirm `{ "bookId": "..." }` for a currently suggested candidate; records its computed method/confidence as a personal copy.                                 |
| `PUT`    | `/book-clubs/:clubId/works/:workId/reading-copy`                 | Manually associate/correct the caller's choice with a source of `shared` or `personal` and a UUID `bookId`; records `manual_confirmation`.                    |
| `DELETE` | `/book-clubs/:clubId/works/:workId/reading-copy`                 | Clear the caller's choice; retains an explicit `none` association for the member/work pair.                                                                   |
| `PATCH`  | `/book-clubs/:clubId`                                            | Owner-only settings or selected-work replacement; omitted optional work metadata is cleared.                                                                  |
| `POST`   | `/book-clubs/:clubId/join`                                       | Join an active instance-visible club as a member. Private clubs require owner-managed membership.                                                             |
| `POST`   | `/book-clubs/:clubId/members`                                    | Owner or moderator adds an instance-local account ID; only owner can assign moderator. Optional role defaults to member.                                      |
| `PATCH`  | `/book-clubs/:clubId/members/:userId`                            | Owner grants or revokes moderator role (`member`/`moderator`). Ownership changes use the transfer route.                                                      |
| `DELETE` | `/book-clubs/:clubId/members/:userId`                            | Owner removes members/moderators; moderator removes members only; a member can leave. Owner must transfer ownership first.                                    |
| `POST`   | `/book-clubs/:clubId/transfer-ownership`                         | Owner transfers ownership to an existing member using `{ "newOwnerUserId": "..." }`; prior owner becomes a member.                                            |
| `POST`   | `/book-clubs/:clubId/archive`                                    | Owner archives the club. Archived clubs are omitted from lists and cannot be joined or modified.                                                              |
| `DELETE` | `/book-clubs/:clubId`                                            | Owner permanently deletes the club; member and selected-work rows are removed by the club foreign-key cascades.                                               |

Club, member, work, and milestone route parameters (`clubId`, `userId`, `workId`, `milestoneId`), and add-member/ownership-transfer/reading-copy/match-confirmation body IDs must be syntactically valid UUIDs; malformed values return `400`.

Schedule reads and all member mapping/progress operations require membership, including for `instance_visible` clubs. Private non-member access returns the same `404 Book club not found`; visible-club non-members receive `403`. Only the owner and moderators may change dates or milestones. Membership, role, selected-work, schedule, reading-copy, mapping, and progress mutations serialize on the club row lock; milestone mappings/progress require the caller's currently selected non-`none` reading-copy association. Clearing or changing that association clears only that member's milestone mapping/progress for the work. Replacing the selected logical work resets its dates/milestones and existing reading-copy choices in the same transaction. These operations never write saved positions, annotations, or other private reader state.

Progress sharing starts disabled. A member must explicitly opt in; opting out immediately suppresses that member's shared summaries while retaining their own progress. Shared schedule responses contain only an opted-in member's account ID and per-milestone status/percentage when that member also has a selected copy. They never contain another member's copy ID, title, author, format, availability, mapping, or reader state. A caller always sees their own private edition mapping and progress in their schedule response.

Reading-copy requests and match discovery require membership even for `instance_visible` clubs. A non-member cannot read, suggest, set, confirm, or clear a private club copy (`404` for private clubs); a non-member of a visible club receives `403`. Choices are per club-member/work. Suggested matches are computed locally from ISBN/external work/edition identifiers first, then normalized title/author/series/volume metadata across book formats; conflicting external work IDs rule out a fallback candidate. Content hashes and file contents are never read or compared. Candidate responses expose only book ID, title, author, method, confidence, and `confirmationRequired: true`. Ambiguous and metadata-based candidates are suggestions only. Confirmation recomputes the current candidate list and revalidates membership and book access before writing. Manual `PUT` associations also support correcting an earlier choice. Setting another source replaces that member's existing choice for the same work; clearing records `source: none` and clears match evidence without deleting the member's book or club work. Reads re-check current library access every time. If an association's book is no longer accessible, the API returns `available: false` and `book: null` without deleting the association. The response exposes only the book `id`, `title`, and `author` when currently authorized; annotations, reading positions, progress, and history are never included.

Self-hosted instances use the existing local book-access behavior for both `shared` and `personal` choices; the source records the member's choice and does not create a new global sharing policy. In Cloud (`CLOUD_MODE=true`), `shared` choices are rejected and personal choices/candidate queries are scoped to the authenticated actor's owned books, including for instance administrators. Progress writes re-check that the member's selected copy is an actor-owned, non-deleted personal book under a write lock; shared summaries are suppressed for stale, non-owned, or deleted copies. Direct non-owned IDs fail with the existing `404 Book not found`; they are not returned or discoverable through reading-copy state or candidate discovery. Existing unauthorized Cloud associations are presented as `source: none`, unavailable, with no book data or match evidence. No Cloud route creates user-to-user copy sharing.

Private-club reads and mutations by non-members return the same `404 Book club not found` response so club existence, membership, and selected-work metadata are not disclosed. For target-member mutations, actor visibility/authorization is checked before looking up the target account's membership. Permission failures for visible clubs return `403`; invalid DTOs or malformed UUIDs return `400`; duplicate membership returns `409`; unauthenticated calls return `401`.

Add-member validates UUID syntax only. This backend has no local user entity or user-directory contract, so it does not verify that the supplied ID identifies an existing account or belongs to this instance; it creates a local membership row for the supplied UUID. Ownership transfer likewise accepts a UUID only when it identifies an existing member of that club. Neither route performs a remote user lookup, sends an invitation, or contacts another instance.

## Deliberate exclusions

This core does not implement invitation tokens/notifications, cross-instance sharing, or discussion. The reading-copy endpoints identify the member's currently authorized local book; reading/downloading content still uses the existing book APIs and their authorization behavior. No club role grants access to another member's books. Club progress is a separate coarse milestone summary; it does not read or aggregate saved positions, annotations, CFIs, page numbers, timestamps, or raw reading history. Deleting a club removes its memberships, logical work, milestones, mappings, progress, and reading-copy associations through foreign-key cascades; it does not delete members' library books.

## Migration and operations

`CreateBookClubCore1790000000003` creates the instance-local club, membership, and logical-work tables. `CreateBookClubReadingCopy1790000000004` adds one source-aware association per membership/work, with foreign keys that retain the association while nulling a deleted book reference. `AddBookClubWorkMatching1790000000005` adds optional identifiers and series metadata to logical works, external IDs to local book/format metadata, and nullable association evidence; existing non-`none` choices are backfilled as member-confirmed manual associations with confidence `1`. `AddBookClubSchedules1790000000006` adds nullable club dates and ordered milestones. `AddBookClubPrivacyProgress1790000000007` adds default-off sharing and member/milestone mapping/progress tables with cascade lifecycle, uniqueness, and range/status checks. These tables contain no reader location/history data. TypeORM runs these migrations at application startup, following existing repository behavior. Reverting the new migrations drops schedule/mapping/progress data; do not revert them against production data without applicable Owner approval and backup/rollback planning.
