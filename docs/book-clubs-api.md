# Book Clubs API (instance-local core)

All routes require the existing JWT authentication guard. The authenticated account ID comes from the verified token; request bodies cannot set the club owner or actor identity. Club roles are local to one club and never grant instance administrator, library administration, or global book-sharing permissions.

## Domain model

- `BookClubEntity` stores name, optional description, `private`/`instance_visible` visibility, active/archived lifecycle, and owner account ID.
- `BookClubWorkEntity` stores a logical selected work's title/author plus optional ISBN, external work ID, edition ID, series, and series position. It does not point to a library book, file, hash, or format.
- `BookClubMemberEntity` stores the per-club account association and `owner`, `moderator`, or `member` role. The legacy `progress_sharing_enabled` column is retained for database compatibility but no longer controls visibility. Its nullable `personal_book_id` remains a reserved legacy placeholder; this feature does not read, write, or return it.
- `BookClubReadingCopyEntity` stores at most one copy choice per club-member and logical work. `source` is `shared`, `personal`, or `none`; an optional local book ID identifies the chosen copy. Confirmed associations also record `associationMethod` (`identifier`, `metadata_candidate`, or `manual_confirmation`) and a `confidence` from 0 to 1. The association is instance-local and independent of file hash or format.
- `BookClubMilestoneEntity` stores ordered, format-neutral named `part`, `chapter`, or moderator-authored `checkpoint` milestones for the selected logical work. Club start/completion dates are optional.
- `BookClubMilestoneMappingEntity` stores a member-only mapping from a club milestone to that member's own edition label/ordinal. It is never included in another member's response.
- `BookClubMilestoneProgressEntity` stores only the member, logical work, milestone, coarse status (`not_started`, `in_progress`, `completed`), and optional 0–100 percentage. Club reading-plan progress is visible automatically to all current members. No book ID, file format, CFI, page number, timestamp, annotation, or reader-history field is stored in this table.
- Clubs, memberships, reading-copy associations, and book pointers exist only in the current instance database. No synchronization, federation, cross-instance invitations, or data transfer is implemented.

## Routes

Book Club selectors can obtain the authenticated caller's own uploaded library through `GET /books/mine`. It accepts the same query, filter, and pagination fields as `GET /books`; its owner scope always comes from the authenticated token, and any `userId` query value is ignored.

| Method   | Path                                                             | Behavior                                                                                                                                                      |
| -------- | ---------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `POST`   | `/book-clubs`                                                    | Create a club; caller becomes owner and initial member. Requires `name`, `visibility`, and `selectedWork: { title, author }`; optional `description`.         |
| `GET`    | `/book-clubs`                                                    | List active instance-visible clubs and private clubs for which caller is a member.                                                                            |
| `GET`    | `/book-clubs/archived`                                           | List archived clubs for which the authenticated caller is still a member; active list behavior is unchanged.                                                   |
| `GET`    | `/book-clubs/:clubId`                                            | Read club and logical selected work, with `currentMembershipRole` (`owner`, `moderator`, `member`, or `null`) for the authenticated caller only. Private clubs require membership. |
| `GET`    | `/book-clubs/:clubId/schedule`                                   | Member reads dates, milestones, their own private mappings, and all current members' coarse progress, including themselves and members who have not started. |
| `PUT`    | `/book-clubs/:clubId/schedule`                                   | Owner or moderator sets optional ISO start/completion dates and replaces the ordered milestone list.                                                          |
| `PATCH`  | `/book-clubs/:clubId/schedule` | Owner or moderator updates dates and an optional ID-aware milestone list, retaining existing step identity and its mappings/progress. |
| `PUT`    | `/book-clubs/:clubId/progress-sharing`                           | Retired: members receive `410 Gone`; club reading-plan progress is automatically visible to all current members. |
| `PUT`    | `/book-clubs/:clubId/milestones/:milestoneId/mapping`            | Member maps a milestone to `{ "memberLabel": "Chapter 7", "memberPosition": 7 }` in their own edition.                                                        |
| `DELETE` | `/book-clubs/:clubId/milestones/:milestoneId/mapping`            | Remove the caller's private edition mapping.                                                                                                                  |
| `PUT`    | `/book-clubs/:clubId/milestones/:milestoneId/progress`           | Record `{ "status": "in_progress", "percentage": 42 }` for a milestone. Only the three coarse statuses and optional 0–100 percentage are accepted.            |
| `GET`    | `/book-clubs/:clubId/works/:workId/reading-copy`                 | Read the caller's choice for that club work, including `source`, match evidence, availability, and a minimal book summary when currently authorized.          |
| `GET`    | `/book-clubs/:clubId/works/:workId/reading-copy/matches`         | List up to 100 suggested local matches, prioritizing stable-identifier matches. Every candidate requires member confirmation; listing creates no association. |
| `POST`   | `/book-clubs/:clubId/works/:workId/reading-copy/matches/confirm` | Confirm `{ "bookId": "..." }` for a currently suggested candidate; records its computed method/confidence as a personal copy.                                 |
| `PUT`    | `/book-clubs/:clubId/works/:workId/reading-copy`                 | Manually associate/correct the caller's choice with a source of `shared` or `personal` and a UUID `bookId`; records `manual_confirmation`.                    |
| `DELETE` | `/book-clubs/:clubId/works/:workId/reading-copy`                 | Clear the caller's choice; retains an explicit `none` association for the member/work pair.                                                                   |
| `PATCH`  | `/book-clubs/:clubId`                                            | Owner-only settings or selected-work replacement; omitted optional work metadata is cleared.                                                                  |
| `POST`   | `/book-clubs/:clubId/join`                                       | Join an active instance-visible club as a member, resolving an outstanding invitation. Private clubs require an accepted invitation.                          |
| `POST`   | `/book-clubs/:clubId/members`                                    | Retired: returns `410 Gone`. Send an invitation instead; no direct-add consent bypass remains.                                                               |
| `GET`    | `/book-clubs/:clubId/members`                                    | Any current club member lists the roster as `{ userId, role }` only, including in archived clubs. Non-members cannot enumerate members; private clubs remain undiscoverable to non-members. |
| `PATCH`  | `/book-clubs/:clubId/members/:userId`                            | Owner grants or revokes moderator role (`member`/`moderator`). Ownership changes use the transfer route.                                                      |
| `DELETE` | `/book-clubs/:clubId/members/:userId`                            | Owner removes members/moderators; moderator removes members only; a member can leave. Owner must transfer ownership first.                                    |
| `POST`   | `/book-clubs/:clubId/transfer-ownership`                         | Owner transfers ownership to an existing member using `{ "newOwnerUserId": "..." }`; prior owner becomes a member.                                            |
| `POST`   | `/book-clubs/:clubId/archive`                                    | Owner archives the club. Archived clubs are omitted from lists and cannot be joined or modified.                                                              |
| `DELETE` | `/book-clubs/:clubId`                                            | Owner permanently deletes the club; member and selected-work rows are removed by the club foreign-key cascades.                                               |
| `GET` | `/book-clubs/:clubId/discussions?revealSpoilers=true` | Member-only discussion list. Spoiler bodies are omitted unless the query is exactly `true`. |
| `GET` | `/book-clubs/:clubId/discussions/:threadId?revealSpoilers=true` | Member reads one visible thread. Spoiler body is omitted unless the query is exactly `true`. |
| `GET` | `/book-clubs/:clubId/discussion-replies/:replyId?revealSpoilers=true` | Member reads one visible reply under a visible, non-deleted parent thread. Spoiler body is omitted unless explicitly revealed. |
| `GET` | `/book-clubs/:clubId/discussion-recovery-targets` | Owner/moderator-only recoverable hidden/deleted discussion target list. Each item is `{ id, type: 'thread' \| 'reply', hidden, deleted }`; it intentionally excludes titles, bodies, spoiler flags, author IDs, and reply text. Ordered by creation time, ID, then type. |
| `POST` | `/book-clubs/:clubId/discussions` | Member creates `{ title, body, spoiler? }`; only owner/moderator may set `promptKind: true`. |
| `PATCH`/`DELETE` | `/book-clubs/:clubId/discussions/:threadId` | Author may edit/delete only own visible, unlocked thread. |
| `GET`/`POST` | `/book-clubs/:clubId/discussions/:threadId/replies` | Member lists or creates replies; locked/hidden/deleted threads reject new replies. |
| `PATCH`/`DELETE` | `/book-clubs/:clubId/discussion-replies/:replyId` | Author may edit/delete only own visible reply (editing also requires an unlocked thread). |
| `POST` | `/book-clubs/:clubId/discussions/:threadId/moderation/:action` | Owner/moderator action: `lock`, `unlock`, `pin`, `unpin`, `hide`, `restore`, or `delete`. |
| `POST` | `/book-clubs/:clubId/discussion-replies/:replyId/moderation/:action` | Owner/moderator action: `hide`, `restore`, or `delete`. |
| `GET` | `/book-clubs/:clubId/discussion-audit` | Owner-only moderation audit with actor, action, target and timestamp. |

Club, member, work, and milestone route parameters (`clubId`, `userId`, `workId`, `milestoneId`), and invitation/ownership-transfer/reading-copy/match-confirmation body IDs must be syntactically valid UUIDs; malformed values return `400`. The retired direct-add route ignores its body and returns `410`.

Active and archived club lists include `currentMembershipRole` for the caller, or `null` for discoverable clubs the caller has not joined. No other member roles are exposed by discovery.

Club lists, detail, and creation responses include an optional, read-only `selectedWork.coverImageFileName` for real cover art at `/uploads/cover-images/:fileName`. Artwork is resolved from matching, non-deleted local books and their formats using the existing identifier-first work matcher. Cloud lookups are restricted to the caller's own books, including for administrators; self-hosted lookups use the existing instance-wide library access. Existing clubs need no migration or reselection. No source book ID, file/format details, reading-copy choice, or private reader state is returned or stored on the logical work, and no reading-copy association is created. A missing or inaccessible cover leaves the field absent; clients should also handle unavailable image files with a fallback. No external artwork service is contacted.

Schedule `PATCH` accepts `{ startDate?, completionDate?, milestones?: [{ id?, name, kind, position }] }`. Omit `milestones` for date-only changes. When provided, the list is the complete desired schedule: IDs must be unique and belong to that club's selected work, omitted existing steps are removed with their dependent mappings/progress, and steps without IDs are created. Retained IDs preserve mappings/progress even when renamed or reordered. All steps and dates are validated before writing. Positions are unique positive database integers; reordering parks retained rows in unused positive positions within the same locked transaction to avoid uniqueness violations. At most 100 steps are accepted. Legacy `PUT` remains a replacement operation, rejects milestone IDs, and deletes/recreates milestones when its list is provided.

Schedule reads and all member mapping/progress operations require membership, including for `instance_visible` clubs. Private non-member access returns the same `404 Book club not found`; visible-club non-members receive `403`. Only the owner and moderators may change dates or milestones. Membership, role, selected-work, schedule, reading-copy, mapping, progress, and discussion mutations serialize on the club row lock. Discussion list, individual thread/reply, reply-list, and moderation-audit reads also hold that lock from authorization through payload retrieval, so concurrent revocation or ownership transfer cannot commit between authorization and response. Ordinary discussion reads support archived clubs for current members; archived writes remain prohibited. Individual reads reject hidden/deleted content, including replies below hidden/deleted parents, even for moderators. Reveal one item with its individual endpoint instead of revealing the list. Milestone mappings/progress require the caller's currently selected non-`none` reading-copy association. Clearing or changing that association clears only that member's milestone mapping/progress for the work. Replacing the selected logical work resets its dates/milestones and existing reading-copy choices in the same transaction. These operations never write saved positions, annotations, or other private reader state.

The web client resolves names with Authentication's `POST /users/display-names`, not admin profiles. It deduplicates IDs and chunks requests to 50; failed lookups offer retry and are not interpreted as former members. Club access changes invalidate discussion/reveal caches, and mutation/refetch lifecycles clear cached bodies so an unsuccessful authorization refetch cannot leave revealed text displayed.

The opt-in PostgreSQL persistence suite exercises the actual schedule/privacy migrations and TypeORM service, not repository mocks. With development `DATABASE_*` connection variables configured, run `BOOK_CLUB_DB_INTEGRATION=true npm test -- --runInBand test/modules/book-clubs/book-club-schedule-persistence.spec.ts`. It creates and removes a unique isolated schema and requires schema-creation permission. It verifies immediate unique-position enforcement, retained mapping/progress row identity through reorder/rename, removed-step cascades, new-step IDs, date-only preservation, invalid-ID rollback, and blocking on the club row's write lock. Do not run integration checks against production.

The cover lookup has a separate opt-in PostgreSQL suite: `BOOK_CLUB_DB_INTEGRATION=true npm test -- --runInBand test/modules/book-clubs/book-club-covers-persistence.spec.ts`. It creates and removes its own isolated schema, checking identifier priority, linked-format artwork, Cloud ownership/deletion filters, private-club concealment, and archived views against real TypeORM queries.

Club reading-plan progress is visible automatically to every current member, including in archived clubs. This applies to existing memberships regardless of the legacy sharing flag, with no data migration required. `sharedProgress` contains one `{userId, milestones}` group for every current member, including the caller, in stable roster order; every current milestone has a coarse status and nullable percentage. Unrecorded steps are `not_started`, including for members without a selected copy. Member groups remain present with an empty milestone list when there is no plan. The response retains `progressSharingEnabled: true` for old read clients; the write preference endpoint is retired rather than falsely promising an opt-out.

Recorded personal/shared progress is used only while the associated selected copy remains active and accessible to that member. Inaccessible, deleted, or stale choices suppress the recorded values without removing that member or exposing the reason; their shared steps use the same `not_started` defaults as any unrecorded progress. Responses never contain another member's copy ID, title, author, format, availability, mapping, or reader state. Private edition mappings remain visible only to their owner. Former members and non-members cannot access club progress, and marking steps never generates activity notifications.

Reading-copy requests and match discovery require membership even for `instance_visible` clubs. A non-member cannot read, suggest, set, confirm, or clear a private club copy (`404` for private clubs); a non-member of a visible club receives `403`. Choices are per club-member/work. Suggested matches are computed locally from ISBN/external work/edition identifiers first, then normalized title/author/series/volume metadata across book formats; conflicting external work IDs rule out a fallback candidate. Content hashes and file contents are never read or compared. Candidate responses expose only book ID, title, author, method, confidence, and `confirmationRequired: true`. Ambiguous and metadata-based candidates are suggestions only. Confirmation recomputes the current candidate list and revalidates membership and book access before writing. Manual `PUT` associations also support correcting an earlier choice. Setting another source replaces that member's existing choice for the same work; clearing records `source: none` and clears match evidence without deleting the member's book or club work. Reads re-check current library access every time. If an association's book is no longer accessible, the API returns `available: false` and `book: null` without deleting the association. The response exposes only the book `id`, `title`, and `author` when currently authorized; annotations, reading positions, progress, and history are never included.

Self-hosted instances use the existing local book-access behavior for both `shared` and `personal` choices; the source records the member's choice and does not create a new global sharing policy. In Cloud (`CLOUD_MODE=true`), `shared` choices are rejected and personal choices/candidate queries are scoped to the authenticated actor's owned books, including for instance administrators. Progress writes re-check that the member's selected copy is an actor-owned, non-deleted personal book under a write lock; shared summaries are suppressed for stale, non-owned, or deleted copies. Direct non-owned IDs fail with the existing `404 Book not found`; they are not returned or discoverable through reading-copy state or candidate discovery. Existing unauthorized Cloud associations are presented as `source: none`, unavailable, with no book data or match evidence. No Cloud route creates user-to-user copy sharing.

Private-club reads and mutations by non-members return the same `404 Book club not found` response so club existence, membership, and selected-work metadata are not disclosed. A successful club read includes only the authenticated caller's `currentMembershipRole`; it is `null` for a visible-club non-member and never exposes any other member's role. For target-member mutations, actor visibility/authorization is checked before looking up the target account's membership. Permission failures for visible clubs return `403`; invalid DTOs or malformed UUIDs return `400`; duplicate membership returns `409`; unauthenticated calls return `401`.

Club invitations validate recipients against the configured Authentication service and require recipient acceptance before creating ordinary membership. See [Social and notifications API](social-api.md) for the complete contract. Ownership transfer still requires an existing accepted club member and does not create membership or contact another instance.

## Deliberate exclusions

This core does not implement cross-instance sharing. Instance-local invitations, friendships, and notifications are documented in [Social and notifications API](social-api.md). It also implements member discussions and moderation audit trails. The reading-copy endpoints identify the member's currently authorized local book; reading/downloading content still uses the existing book APIs and their authorization behavior. No club role grants access to another member's books. Club progress is a separate coarse milestone summary; it does not read or aggregate saved positions, annotations, CFIs, page numbers, timestamps, or raw reading history. Deleting a club removes its memberships, logical work, milestones, mappings, progress, reading-copy associations, discussions, and discussion audit rows through foreign-key cascades; it does not delete members' library books.

## Migration and operations

The all-member progress persistence suite uses `SOCIAL_TEST_DATABASE_URL` pointing to a non-production PostgreSQL database with schema-creation permission. Run `npm test -- --runInBand test/modules/book-clubs/book-club-progress.persistence.spec.ts`; it creates and removes an isolated schema. Coverage includes visibility across members despite legacy sharing flags, missing-copy defaults, completion/undo, removal and outsider boundaries, empty archived plans, and Cloud ownership revocation.

`CreateBookClubCore1790000000003` creates the instance-local club, membership, and logical-work tables. `CreateBookClubReadingCopy1790000000004` adds one source-aware association per membership/work, with foreign keys that retain the association while nulling a deleted book reference. `AddBookClubWorkMatching1790000000005` adds optional identifiers and series metadata to logical works, external IDs to local book/format metadata, and nullable association evidence; existing non-`none` choices are backfilled as member-confirmed manual associations with confidence `1`. `AddBookClubSchedules1790000000006` adds nullable club dates and ordered milestones. `AddBookClubPrivacyProgress1790000000007` adds default-off sharing and member/milestone mapping/progress tables with cascade lifecycle, uniqueness, and range/status checks. `AddBookClubDiscussions1790000000008` adds member discussions, replies, and moderation-audit rows; `EnforceBookClubDiscussionReplyClub1790000000009` prevents a reply from referencing a thread in another club. These tables contain no reader location/history data. TypeORM runs these migrations at application startup, following existing repository behavior. Reverting the new migrations drops schedule/mapping/progress/discussion data; do not revert them against production data without applicable Owner approval and backup/rollback planning.
